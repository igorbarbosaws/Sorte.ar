# Sorte.ar — Backend

Node.js 20 + Express 5 API server for user profiles and social features.

## Tech stack

| Layer | Technology |
|---|---|
| Runtime | Node.js 20 |
| Framework | Express 5 |
| Database | PostgreSQL 16 |
| ORM | Drizzle ORM |
| Auth | JWT (access + refresh) + bcrypt |
| Validation | Zod |
| Avatar storage | Cloudinary |
| Rate limiting | express-rate-limit + Redis |
| Testing | Vitest + fast-check |

## Getting started

### 1. Install dependencies

```bash
cd server
npm install
```

### 2. Configure environment variables

```bash
cp .env.example .env
# Edit .env and fill in DATABASE_URL, JWT_SECRET, REDIS_URL, CLOUDINARY_* values
```

### 3. Apply the database migration

> **Important:** A running PostgreSQL instance is required. Set `DATABASE_URL` in `.env` first.

```bash
npm run db:migrate
```

The migration file is at `src/db/migrations/0000_initial_schema.sql`.
It creates all tables: `users`, `refresh_tokens`, `championships`,
`friend_requests`, `friendships`, and `player_links`.

### 4. Run in development mode

```bash
npm run dev
```

### 5. Type-check

```bash
npm run typecheck
```

### 6. Run tests

```bash
npm test
```

## Directory structure

```
server/
  src/
    app.ts                  # Express app + server bootstrap
    modules/
      auth/                 # Register, login, logout, refresh
      profile/              # Public profile, display name, avatar
      championship/         # CRUD, score updates, finalization
      friend/               # Friend requests, list, remove
      player-link/          # Player ↔ user links
      migration/            # localStorage → DB migration
    middleware/
      authenticate.ts       # JWT verification
      authorize.ts          # Ownership check factory
      rate-limit.ts         # express-rate-limit configs
    db/
      schema.ts             # Drizzle table definitions
      index.ts              # pg Pool + drizzle instance
      migrations/           # SQL migration files
    lib/
      jwt.ts                # sign / verify access tokens
      storage.ts            # Cloudinary upload/delete
      validation.ts         # Shared Zod schemas
  drizzle.config.ts
  tsconfig.json
  vitest.config.ts
  .env.example
```

## Database schema notes

- All IDs are UUID v4 generated by the database (`gen_random_uuid()`).
- `championships.local_id` has a **partial unique index** on `(creator_id, local_id) WHERE local_id IS NOT NULL` to support idempotent localStorage migration.
- `friendships.user_a < friendships.user_b` constraint ensures no duplicate reverse-order rows.
- `friend_requests` has a `CHECK (from_user <> to_user)` constraint to prevent self-friend requests at the DB level.
